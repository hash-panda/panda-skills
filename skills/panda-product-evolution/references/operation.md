# 工作流与跨轮学习

在接入已有持续任务、恢复中断回合或改进 Agent 方法时使用。

## 分清落点

| 载体 | 负责什么 |
| --- | --- |
| 本 Skill | 读取证据、选择回路、设计实验、实施验证、提炼经验的方法 |
| 项目 EXTEND.md / 既有项目文档 | 用户目标、指标、边界、预算、授权和证据位置 |
| 既有调度器/工作流 | 定时或事件触发、数据获取、运行锁、重试、超时、通知 |
| 项目实验记录 | 假设、版本、原始结果、失败方案、待观察项和下一步 |

不因为安装本 Skill 就宣称已经建立后台自迭代。只有实际配置并验证调度后，才能报告周期任务可运行。
用户没有要求周期运行时，完成本次回合即可；不要自动创建提醒、发布消息或修改其他项目。

## 恢复与运行

1. 读取项目配置和最近一轮记录，确认现有版本、未完成动作和待观察结果。
2. 检查相同实验是否仍在执行或等待观察；复用现有实验 ID，避免重复实施或重复发布。
3. 固定本轮数据截止时间、资源上限和本轮交付目标。
4. 完成一个有界实验；任务明确授权多轮时，逐轮保存证据，满足停止条件即停止。
5. 先处理上一轮结果，再增加新候选。观察未结束时可以处理独立工作，但不得提前宣告改善。

如果没有持久记录能力，向用户提供本轮记录并明确限制；不要声称已形成跨会话记忆。

## 经验的最小字段

对值得复用的经验记录：

- **触发条件**：何种任务、版本、负载或用户场景适用。
- **规则或动作**：下次具体做什么。
- **证据**：实验、提交、测试/日志位置；与经验关联的原始结果。
- **边界与反例**：什么情况下可能不成立。
- **状态**：待验证、在本项目有效、跨任务有效、已失效。
- **复查条件**：环境/模型/产品变化，或新的反例。

单次有效经验可以改善下一轮的假设，但先保留其有限范围；不能立即把它升级成所有项目必须遵循的通用规则。
失败实验同样保留：记录为什么失败、哪些假设被排除、什么新证据出现时值得重试。

## 改进改进方法

将候选方法与原方法比较，例如诊断顺序、上下文构建、方案筛选、工具设计或实验选择。

1. 说明方法变更预期改善的是有效改进率、诊断时间、验证成本，还是收益预测的准确性。
2. 固定任务分布、资源条件、评估口径和基线方法版本。
3. 在没有参与方法修订的新任务上运行，保留失败与无变化结果。
4. 区分任务能力的改善、产品自身变化带来的收益，以及评估难度变化。
5. 证据成立后，将适用范围内的方法固化到项目规则或共享 Skill；不成立时保留原方法。

不得自动重写用户价值目标、授权范围或验收规则来提高成绩。可以提出修改建议，并把它作为独立的决策与重新建基线过程。

## 可复用的工作流调用语句

> 使用 panda-product-evolution，读取本项目目标、最新基线与上轮记录，完成一轮证据驱动改进。在已有授权和本轮预算内执行并验证；结果等待真实数据时标为待观察，保存可恢复记录并说明下一次检查条件。

## 设计来源与范围

此 Skill 将“双环改进 + 跨轮学习”作为工程组织方法，不把它表述成统一的 RSI 学术分级。
参考 [Agent Skills 开放规范](https://agentskills.io/home) 的按需加载结构；参考 [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) 将自我修改与实证评估相连接的研究思路。
这些参考不证明本 Skill 已具备自主研究、长期经营或保证收益的能力；这些效果需要在实际项目中验证。
